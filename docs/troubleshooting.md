# Диагностика

Ниже собраны типовые проблемы Sheller и способы их устранения. Для проверки гипотез запускайте приложение в режиме разработки (`npm run dev`) — сообщения main-процесса выводятся в консоль.

## Подключение

| Симптом | Вероятная причина | Решение |
|---------|-------------------|---------|
| `ECONNREFUSED` | SSH-сервер не слушает порт | Проверьте `sshd`, порт и firewall |
| Тайм-аут | Неверный хост, сеть или прокси | Проверьте адрес, VPN и настройки прокси |
| `ENOTFOUND` | Опечатка в имени хоста | Проверьте DNS и написание |
| `Authentication failed` | Неверный пароль, ключ или пользователь | Проверьте учётные данные и `authorized_keys` |
| Ключ отклонён | Права на файл ключа | На сервере: `chmod 600 ~/.ssh/authorized_keys`; локально проверьте доступ к файлу |
| Ошибка парольной фразы | Неверная фраза или формат ключа | Укажите фразу в профиле или используйте агент |
| Агент не работает | Агент не запущен | Запустите Windows OpenSSH Agent или задайте `SSH_AUTH_SOCK` |
| Ошибка jump-хоста | Промежуточный профиль недоступен | Подключитесь к jump-хосту напрямую и проверьте цепочку |
| Прокси отклоняет соединение | Неверный тип, порт или учётные данные | Проверьте SOCKS5/HTTP, хост, порт и логин |

## Host key

| Симптом | Решение |
|---------|---------|
| Запрос отпечатка при первом подключении | Сверьте отпечаток с сервером и подтвердите |
| «Ключ изменился» | Не подтверждайте без проверки; сравните отпечаток через консоль сервера |
| Нужно обновить ключ после переустановки сервера | Подтвердите новый отпечаток только после проверки |

## Mosh

| Симптом | Решение |
|---------|---------|
| `mosh-server` не найден | Установите Mosh на сервер: `sudo apt install mosh` |
| Терминал не открывается, SSH работает | Откройте UDP 60000–61000 на сервере и в firewall |
| `mosh-client` не найден | Переустановите Sheller, проверьте `PATH` или укажите путь в профиле |
| WSL: клиент не найден | Выполните `sudo apt install mosh` внутри WSL |
| Сессия не переживает смену сети | Проверьте, что используется Mosh, а UDP не блокируется |

## Туннели и файлы

| Симптом | Решение |
|---------|---------|
| `EADDRINUSE` | Локальный порт занят — измените `bindPort` или укажите `0` |
| Удалённый туннель не работает | Проверьте `AllowTcpForwarding` и права пользователя |
| Порт <1024 не открывается | Запустите с правами администратора или используйте порт выше 1024 |
| SFTP: `Permission denied` | Проверьте права каталога и пользователя |
| SFTP не открывается | Убедитесь, что используется SSH/Mosh, а sftp-подсистема включена |
| Передача зависла | Отмените передачу и проверьте сеть; одновременно идёт не более двух файлов |
| ZMODEM не срабатывает | Установите `lrzsz` на сервере (`sz`/`rz`) |

## Cron и мониторинг

| Симптом | Решение |
|---------|---------|
| «Не удалось прочитать crontab» | Проверьте `crontab -l` вручную и права пользователя |
| «Не удалось сохранить crontab» | Проверьте, что `crontab` доступен и не заблокирован администратором |
| Графики пустые | Нужен Linux и утилиты `vmstat`, `free`, `df`; для Telnet мониторинг недоступен |
| Температура `0` | Датчик `/sys/class/thermal` отсутствует или недоступен |

## Приложение

| Симптом | Решение |
|---------|---------|
| Окно закрылось, но процесс работает | Приложение остаётся в трее — завершите через меню трея |
| Обновление не находится | Автообновление работает только в установленной версии; проверьте Releases |
| Ошибка сборки `node-pty` | Установите Visual Studio Build Tools и переустановите зависимости |
| Пустой экран после сборки | Запустите `npm run build` и проверьте консоль; в production действует CSP |
| Нужно посмотреть ошибку main-процесса | Запустите `npm run dev` и откройте консоль терминала |

## Что приложить к обращению

- Версию Sheller и Windows.
- Протокол (SSH/Mosh/Telnet) и используется ли jump-хост/прокси.
- Точный текст ошибки из интерфейса.
- Шаги, после которых проблема воспроизводится.
- Для проблем сборки — вывод `npm run typecheck` и `npm run build`.

Не прикладывайте пароли, приватные ключи и их содержимое.
