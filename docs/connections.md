# Подключения

Профиль подключения хранит протокол, адрес, способ аутентификации, jump-хост, прокси и туннели. Один профиль можно использовать для нескольких сессий.

## Протоколы

| Протокол | Порт по умолчанию | Шифрование | Особенности |
|----------|-------------------|------------|-------------|
| SSH | 22 | Да | Полноценный терминал, SFTP, туннели, Cron, мониторинг |
| Mosh | 22 для bootstrap | Да | Переживает разрывы и смену сети; нужен `mosh-server` и UDP 60000–61000 |
| Telnet | 23 | Нет | Только терминал; вход выполняется в самом терминале |

## Аутентификация

| Метод | Что указывается | Хранение |
|-------|-----------------|----------|
| Пароль | Пароль в профиле или запрос при каждом подключении | Зашифрован через `safeStorage`, если не выбран запрос |
| Приватный ключ | Путь к файлу ключа и парольная фраза (опционально) | Путь хранится в профиле, фраза шифруется |
| SSH-агент | Ничего; используется агент ОС | Ключи остаются в агенте |

Для SSH-агента Sheller использует `SSH_AUTH_SOCK`, а на Windows — именованный канал OpenSSH Agent (`\\.\pipe\openssh-ssh-agent`).

## Jump-хосты

Поле **Jump-хост** ссылается на другой сохранённый профиль. Поддерживаются цепочки произвольной длины.

- Каждый hop подключается со своими настройками аутентификации и прокси.
- Циклические цепочки запрещены и отклоняются при сохранении.
- Jump-профиль должен существовать; при импорте отсутствующий hop вызывает ошибку.
- Host key проверяется для каждого hop отдельно.

## Прокси

| Тип | Назначение |
|-----|------------|
| `none` | Прямое подключение |
| `socks5` | SOCKS5-прокси с опциональной аутентификацией |
| `http` | HTTP-прокси (CONNECT) с опциональной аутентификацией |

Прокси можно задать для целевого сервера и для jump-хостов. Пароль прокси хранится в зашифрованном виде.

## Дополнительные параметры

| Параметр | Описание |
|----------|----------|
| Keepalive | Интервал keepalive-пакетов SSH в миллисекундах; по умолчанию 15000 |
| Bind address | Локальный адрес, с которого устанавливается исходящее соединение |
| Mosh client path | Путь к `mosh-client`, WSL или MSYS2, если не нужен встроенный клиент |
| Запрос пароля | Не сохранять пароль и спрашивать при каждом подключении |

## Host key

При первом подключении Sheller показывает отпечаток ключа сервера. После подтверждения отпечаток сохраняется в профиле.

- При изменении ключа выводится предупреждение с предыдущим отпечатком.
- Не подтверждайте новый ключ без проверки: это может указывать на подмену сервера.
- Для jump-хостов отпечатки хранятся в их собственных профилях.

## Mosh: порядок поиска клиента

1. Путь, указанный в профиле (файл `mosh-client` или `wsl.exe`).
2. Встроенный клиент из установщика Sheller.
3. `mosh-client` в `PATH`.
4. `C:\Program Files\Mosh`, MSYS2 и Cygwin.
5. WSL, если в нём установлен `mosh-client`.

Для WSL установите пакет:

```bash
sudo apt install mosh
```

Mosh использует SSH для запуска `mosh-server`, после чего обменивается данными по UDP. Если UDP закрыт, терминал не откроется, хотя SSH-подключение может выглядеть успешным.

## Открепление сессии

Активную сессию можно открепить в отдельное окно. Соединение при этом не разрывается, потому что `SessionManager` находится в main-процессе и общий для всех окон.
