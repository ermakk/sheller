# Базовые правила проекта Sheller

> Автоматически определённые соглашения по коду. При необходимости редактируйте вручную.

## Именование

- Файлы модулей: `camelCase.ts` (`profiles.ts`, `sessions.ts`, `updater.ts`)
- React-компоненты: `PascalCase.tsx` (`ConnectionModal.tsx`, `TerminalPane.tsx`)
- Переменные и функции: `camelCase` (`loadProfiles`, `resolveChain`, `tunnelRoute`)
- Классы и интерфейсы: `PascalCase` (`ProfileStore`, `SessionManager`, `ConnectionProfile`)
- Константы: `UPPER_SNAKE_CASE` (`TUNNEL_TYPES`, `CHECK_INTERVAL_MS`, `RESERVED_SHORTCUTS`)
- IPC-каналы: строки вида `domain:action` (`session:connect`, `event:session-status`), централизованно в `src/shared/types.ts`

## Структура модулей

- `src/main/` — главный процесс: окна, трей, IPC-обработчики, сервисы и хранилища
- `src/preload/` — единственный мост `contextBridge`; новые API добавляются сюда и в типы `ShellerApi`/`UpdaterApi`
- `src/renderer/src/` — React-приложение; компоненты в `components/`, общие утилиты в `utils.ts`
- `src/shared/` — общие типы, IPC-контракты и утилиты без зависимостей от Electron
- Импорты: `node:`-префикс для встроенных модулей, `import type` для типов, алиасы `@shared` и `@renderer`

## Обработка ошибок

- На границе IPC ошибки перехватываются и возвращаются как `{ ok: false, error }`; успех — `{ ok: true, ... }`
- Используйте `describeError`/`errorMessage` для приведения ошибок к строке
- Пользовательские сообщения об ошибках — на русском языке
- В renderer ошибки показываются через тосты (`addToast('error', ...)`), а не через `alert`
- Не добавляйте «голые» `throw` в UI-код без обработки; не раскрывайте секреты в сообщениях

## Control Flow

- Предпочитайте плоский, читаемый поток управления вместо глубокой вложенности. Используйте guard clauses, ранние `return`/`continue`, небольшие именованные хелперы или явную классификацию, когда это упрощает чтение. Обрабатывайте граничные и нерелевантные случаи раньше, чтобы основной путь оставался видимым.

## Логирование

- В main-процессе допустимы `console.warn`/`console.error` для диагностики (например, проблемы с иконкой трея или чтением хранилища)
- В renderer не логируйте в консоль; используйте существующую систему тостов
- Никогда не логируйте пароли, парольные фразы и содержимое приватных ключей

## Форматирование

- Отступ — 2 пробела
- Одинарные кавычки, без точек с запятой
- Явные типы возврата у экспортируемых функций и обработчиков IPC
- `unknown` для внешних/непроверенных значений с последующим сужением типа

## Проверки

- Перед завершением изменений запускайте `npm run typecheck` и `npm run test`
- Новую функциональность покрывайте тестами Vitest; renderer-тесты требуют docblock `// @vitest-environment jsdom`
- Дополнительно проверяйте сценарии вручную через `npm run dev`
